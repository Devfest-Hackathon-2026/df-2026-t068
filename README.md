# IdeaWeave

複数のアイデアを因数分解し、案を横断する意味的な接点を可視化するWebアプリです。

## 公開URL

https://ideawave-865686179714.asia-northeast2.run.app

Googleログイン後、プロジェクトを作成して2〜5件の案を入力すると、各案を6つの因数へ分解します。異なる案に含まれる近い意味と上位概念を可視化し、組み合わせを考える材料として確認できます。

## 主な機能

- Googleログインとプロジェクトの保存
- 2〜5案の入力と6因数への分解
- 異なる案に含まれる因数の意味比較
- 具体的な類似と上位概念の関連を分けた表示
- A–B、B–CからA–Cを推測しないペア単位の判定
- ノード配置と分析結果の自動保存

## 使用したGoogle技術

- Firebase Authentication：Googleログイン
- Cloud Firestore：プロジェクト、分析結果、ノード配置の保存
- Firebase App Hosting：Next.jsアプリと分析APIの公開
- Vertex AI：Geminiによる因数抽出と共通ラベル確認、Embeddingによる意味比較

AIの認証情報はサーバー側だけで扱います。ブラウザはFirebase IDトークンを付けて自アプリの分析APIを呼び出し、APIは利用者本人のプロジェクトだけを読み込みます。

## ローカル起動

```bash
npm install
npm run dev
```

ブラウザで `http://localhost:3000` を開きます。

## 分析アルゴリズムの開発

`algorithm/`は独立したTypeScriptパッケージです。プロジェクト詳細の入力・マップと、認証済みの`/api/analyze`を介して接続しています。

```bash
npm --prefix algorithm ci
npm --prefix algorithm run typecheck
npm --prefix algorithm test
```

2案の入力テストは`algorithm/`へ移動して`npm run try`を実行します。API設定と認証は[接続手順](algorithm/VERTEX_SETUP.md)、APIを使わない再評価は[説明書](algorithm/README.md)を参照してください。

アプリとアルゴリズムを両方開発する場合はNode.js 22.18以上を使用してください。それぞれのパッケージで依存関係を導入し、型検査・テストを実施します。

## Firebase Authentication

1. Firebase ConsoleでWebアプリを登録します。
2. Authenticationのログイン方法でGoogleを有効にします。
3. `.env.example`を`.env.local`へコピーし、WebアプリのFirebase構成を設定します。

`.env.local`はGitの管理対象外です。Firebase構成以外の秘密情報もコミットしないでください。

## Cloud Firestore

プロジェクトは `users/{uid}/projects/{projectId}` に保存します。`firestore.rules`は、ログイン中のUIDとパスのUIDが一致する場合だけ読み書きを許可します。

新規作成時には名称、状態、入力版、グラフ版、分析対象版、作成日時、更新日時を初期値として保存します。

## プロジェクト内の分析ワークスペース

1. `.env.example`を参考に、ルートの`.env.local`へFirebaseの公開設定とGoogle Cloudのサーバー設定を記入します。`algorithm/.env`はCLI専用で、Webアプリからは読みません。
2. ローカルでは`gcloud auth application-default login`で認証します。公開時は実行用サービスアカウントにAI呼び出し権限を付けます。AIの認証情報を`NEXT_PUBLIC_*`へ置かないでください。
3. `npm ci`、`npm run dev`を実行し、Googleログイン後にプロジェクトを開きます。
4. 2〜5案を入力し、「アイデアをマッピング」を押します。この操作は実APIを呼び、利用料金が発生します。

各案の6因数をツリーに表示し、近い値を点線と暫定共通ラベルでつなぎます。説明・根拠やベクトル数値は画面に出しません。ノードは移動・拡大縮小できます。入力は約0.9秒後、配置は操作終了後に保存されるため、保存が終わってからページを閉じてください。

マップの既定表示は「因数ごとに比較」です。ターゲットなど一つの因数を選ぶと、左に各アイデア、中央に元の因数値、右に共通値を表示します。線上にはラベルを置かず、共通値ノードにまとめます。ノードをクリックすると関係するノード・線を強調し、空白のクリックまたは「選択を解除」で戻せます。「全体ツリー」では全因数を俯瞰し、案を横断する線は表示しません。因数別比較と全体ツリーの配置は別々に保存します。

意味の類似から共通値をまとめる際は、同じグループの全ペアに関係があることを確認します。A–B、B–CだけでA–Cを勝手に推定しません。橙はAIが抽出した上位概念同士の類似を示し、具体値の緑の類似関係とは別ノードです。現在は全因数の上位概念をAIで抽出してベクトル比較します。固定の対象分類表は廃止しました。[処理の説明](algorithm/ABSTRACTION.md)を参照してください。

保存先は`users/{uid}/projects/{projectId}/workspace/current`です。入力、分析時の入力、表示用の分析結果、配置を保存し、Embeddingや候補ベクトルは保存しません。入力を変更しても前回のマップを保持し、内容が異なれば再分析が必要と表示します。別画面と入力版が競合したときは、古い結果の保存を拒否します。プロジェクト一覧と同じ所有者ルールを使うため、既存の`firestore.rules`で動作します。

分析APIはFirebase IDトークンを検証し、同じトークンでFirestoreから本人のプロジェクト・保存済み入力を読みます。クライアントがモデルや任意のプロンプトを指定することはできません。未ログインは401、存在しない／参照できないプロジェクトは404／403になります。

同一サーバープロセスでは利用者ごとの同時実行を1件に制限し、10秒間隔を設けます。複数インスタンス間での厳密な利用上限ではありません。一般公開の運用規模を広げる場合は、分散した実行制御と利用上限を追加してください。

```bash
npm test
npm run lint
npm run build
npm --prefix algorithm run typecheck

```

ブラウザでは、2案の分析、入力の追加・削除、入力変更後に前回の結果が残ること、再読み込み後に入力と結果・配置が復元されることを確認します。失敗時も入力を残し、同じボタンから再試行します。

## 全因数と上位概念の表示

各値は具体的な語句1つを保ち、別に上位概念の候補を1つ持ちます。全案×6因数の一覧を常時表示し、共通リンクがない値も省略しません。具体的な類似は緑、上位概念の関連候補は橙の共通値ノードへ接続します。以前の結果には上位概念がないため、再分析ボタンを押すまで旧結果を保持して案内を表示します。表示を開いただけでAI APIを呼び出すことはありません。
