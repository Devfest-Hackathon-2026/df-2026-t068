# 全体マップと共通ラベルの改善

## 全体マップ
アイデアをカードにし、実際の比較ペアがある二案を一本の線で結ぶ。因数の数が線の太さ。同因数の具体値・上位概念は一件に集約し、具体値を優先。推移的に未確認の関係を足さない。上位概念だけなら点線。線・接続ボタンで元の二値と共通ラベルを開き、因数別表示へ移動できる。非共通の因数は下の一覧に全件残す。配置保存はnetwork:名前空間を使用。

## 共通ラベル
平均ベクトルと両メンバーへの近さで候補を順位付けした後、非同一値の候補をまとめて一回のLLM呼び出しで確認する。双方を含む自然な意味か、片方だけの条件を追加していないか、否定・増減を混同していないかを見る。受理された候補だけから順位の高いものを選ぶ。受理候補がない場合は「意味の近い値」「上位概念の関連候補」という中立表示を使用し、ベクトル上の接続自体は候補として残す。LLM確認も誤判定し得るので、厳密な包含関係の証明ではない。

具体値と上位概念は別経路で比較し続ける。確認で関連性を第三種に自動分類する機能は追加していない。因数一つにつき値は一つのまま。

API追加は分析一回あたり最大一回（非同一値のラベル候補がある場合）。同一ラベルは確認不要。reviewLabels未対応の独自Providerは従来動作でverification=unverified。保存結果にapprovedLabelsを保持し、offline replayは過去の確認だけを再使用する。旧形式には新たな意味判断を追加しない。

## 表示名と比較テキスト
config/default.jsonのembeddingModeはlabel（従来）を維持。meaningへ切り替えると「短い値：当該因数だけの説明」をベクトル化する。contextと違い根拠原文全体を加えない。比較方式を変えた場合は既存ベクトルを再利用できないため再分析が必要。実データで優劣を未検証なので、meaningを標準採用したとはしない。

## 因数ごとの基準をオフライン調整
npm --prefix algorithm run calibrate -- <入力JSONのパス>

入力JSONはanalysis（CLIで保存したフル分析結果）とjudgmentsの二つを持つ。judgmentsの一件はsource、target（因数値ID）、factorId、level（directまたはbroader）、expected（つなぐべきならtrue）を指定。analysis.comparisons/broaderComparisonsの保存済みスコアを使い、因数・段階別にF1最大のしきい値を提案する。同点なら適合率、さらにしきい値の高さを優先。正例・負例の両方がなければ提案しない。重複や未保存ペアはエラー。

外部APIの呼び出し・設定の自動書き換えは行わない。出力は学習例での成績であり、別の評価例で確認してからfactorThresholds/abstractionFactorThresholdsへ反映する。短い語同士の数値を恣意的に作って基準を最適化しない。UI保存結果はベクトル非保存だがスコアはあるので、必要な比較スコアを含む形式を渡せば調整可能。

## 検証範囲
ローカルの模擬Provider、保存結果によるUI確認、型チェック、lint、本番ビルド。実モデルによる精度向上や意味比較方式の優位性は未実証。保存済みプロジェクトは自動再分析しない。


## 共通原理の取りこぼし対策（2026-11-09）
従来は具体値0.82・上位概念0.86を超えたペアしか検討しなかったため、長い複合値や抽象化のばらつきで同じ処理が見落とされた。
通常の判定は維持し、未接続の同因数ペアについて具体値または上位概念の類似度がsemanticCandidateThreshold（既定0.6）以上なら意味確認の候補へ送る。これは接続の合格基準ではない。候補上限maxSemanticPairs（既定20、0で無効）、除外済みペアは対象外。
一括生成で双方に根拠がある共通部分を最大3表現（conceptとalternatives最大2件）提案する。語句・説明・元の上位概念を参照し、特定の入力用辞書は使わない。各因数の値は一つのまま。候補は両側ベクトルとの最低類似度0.5等を満たし、さらに別の一括ラベル確認で双方に実在する共通部分と認められた場合のみ接続する。片方の数量提案などを足したラベルは除外できる。確認不能なら接続しない。
復元リンクはmethod=semanticを保存。scoreは元の比較値のままであり、合格値へ書き換えない。比較欄は「意味確認」として通常の基準判定と区別する。semanticDecisionsに候補生成の結果を保持し、CLI保存データではオフライン再現可能。
追加APIは候補がある場合の一括生成一回と、従来の一括ラベル確認の対象追加。計算量・トークンは増えるため無制限の再試行はしない。意味確認にはLLMの誤りが残り、全ての共通部分を保証するものではない。
実モデル検証のベクトルは直交基底へ射影して内積を保持した小さなfixtures/semantic-live.jsonとして回帰テストに利用する。模擬スコアだけで改善したとは判定しない。
