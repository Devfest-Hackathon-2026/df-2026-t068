# APIを使わない改善

今回の変更作業では外部AI APIを呼んでいません。型検査・モック・保存済みの出力・人工ベクトルのテストで確認しています。自然言語の精度改善を実証したという意味ではありません。

## 共通ラベルの選択

従来は平均ベクトルとのコサイン類似度だけで順位を決めていました。平均の近くでも元の片方に偏った候補が選ばれる可能性があるため、各候補について以下を計算します。

- `score`：平均ベクトルへのコサイン類似度
- `memberScore`：元の各値へのコサイン類似度の最小値
- `eligible`：上の2値がそれぞれ設定した最低基準を満たすか

候補は、基準を満たすものを優先し、その中でmemberScoreが高いもの、同点ならscoreが高いものを選びます。これにより、片方だけに似たラベルを避けやすくします。新しい言葉を必ず選ぶわけではなく、元の語が最適なら残します。両側への近さは意味の正しさを保証しないため、候補は暫定です。

`minimumLabelMemberSimilarity`の既定は仮の0.5です。類似度と同様、正例・負例で今後評価します。すべて基準外なら元の語へフォールバックします。

## 因数ごとの基準

ターゲットの一致と解決原理の一致は、同じスコア基準が最適とは限りません。`factorThresholds`で因数ごとに上書きできます。

```json
{
  "similarityThreshold": 0.82,
  "factorThresholds": {
    "purpose": 0.75,
    "mechanism": 0.85
  }
}
```

この数字は使い方の例であり推奨値ではありません。既定のfactorThresholdsは空で、未検証の調整値を勝手に採用していません。

## 重複処理の削減

全角・半角、前後の空白、連続する空白を整えます。両者が同じラベルならLLMによるラベル候補生成を省略し、その語を共通ラベルとして使います。同じ語のEmbeddingは従来どおり分析内で再利用します。意味の同義語を辞書なしで同一扱いにする処理は追加していません。

## API消費なしの再評価

```powershell
npm run replay
npm run replay -- --threshold=0.7
npm run replay -- output/analysis.json --threshold=0.75
```

既定では`output/interactive-analysis.json`を読み、既存の因数とベクトルで比較・平均・ラベル順位を計算し直します。元ファイルは上書きせず、結果を`output/replay-analysis.json`へ保存します。説明と根拠は表示しません。入力したアイデアの再解釈や新しい語句の生成は行いません。

新しい出力にはラベル候補のベクトルと設定も保存するため、候補を再評価できます。過去の出力に候補ベクトルがない場合は、ベクトルが保存されている元の語などに限って選びます。しきい値を下げて新しく採用されたペアにも、新しい候補をLLMで生成しません。したがってAPI使用時のラベル候補全体を再現できるとは限りません。

候補のベクトルがなくてもAPIへ取りに行くことはありません。Embeddingへの入力方式を変更した場合は既存のベクトルを使い回さずエラーにします。新しい出力から因数の定義を変更した場合もエラーにします。古い出力には定義が保存されていないため、因数の意味を変えずに使用してください。

`--config=設定ファイル.json`で評価設定を明示できます。指定がなければ保存時の設定を使います。`--threshold`を指定すると因数ごとの上書きを外して、全因数にその値を適用します。

## 判定の限界

ベクトルが近いことは同意・因果関係・実現可能性の保証ではありません。特に「増やす／減らす」などは語彙が似ていても逆の目的になることがあります。単純な否定語の置換では誤判定も多いため、今回は自動で反転・排除する処理を入れていません。LLMの推測を含む共通部分は表示で区別します。

しきい値の調整は、保存した複数の例について、人が「近い／違う」を決めて比較する必要があります。1組の例だけに合わせて基準を下げることは避けています。
