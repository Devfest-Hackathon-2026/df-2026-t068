# 具体的な値と上位概念の比較

固定の「大学生」などの分類表は廃止しました。現在はどの因数でもLLMが一段階上の概念を提案し、Embeddingで上位概念同士を比較します。分類先を事前に列挙する必要はありません。

## 抽出

同じ1回の抽出要求で、各因数の具体値と上位概念を取得します。どちらも短い文字列1つ、またはnullです。配列へ増やしません。

```json
{
  "factors": {"target": "旅行好きの大学生", "mechanism": "売上履歴による仕入れ予測"},
  "abstractions": {"target": "大学生", "mechanism": "需要予測"}
}
```

実際には設定された全因数と、原文根拠などのdetailsを返します。元の値はそのまま保持します。上位概念は包含関係を意図したAIの候補であり、意味の正しさや抽象度の一致を保証するものではありません。「人」「問題」「個人」など極端に広い語は除外します。適切な上位概念がなければnullにします。

## ベクトル比較

1. 元の値をEmbeddingでベクトル化します。
2. 上位概念も同じモデルでベクトル化します。同じ文字列の重複要求は分析内で再利用します。
3. 異なるアイデアの同じ因数だけを比較します。ターゲットの上位概念と目的の上位概念などを混ぜません。
4. 具体値のコサイン類似度は既定0.82、上位概念は独立した基準の0.86で判定します。これらは仮の値であり、精度評価済みの最適値ではありません。
5. 上位概念の近いペアについても平均ベクトルと候補語を比較し、暫定ラベルを選びます。元の値を共通ラベルで置き換えません。

しきい値は`abstractionThreshold`、因数別の上書きは`abstractionFactorThresholds`で設定します。具体値と上位概念にはそれぞれ比較スコアを保存します。

CLIの詳細結果は`broaderConcept`と`broaderVector`、`broaderComparisons`、`broaderPairs`を含みます。Web表示では大きなベクトルを除き、元の語、上位概念、比較スコアとリンクだけを保存します。

## 表示

- 全案×6因数の一覧を常時表示し、共通リンクがない値も表示します。
- 各セルに元の語と上位概念を表示します。
- 緑の共通値ノードは具体値の類似、橙のノードは上位概念の関連候補を示します。
- まとめる場合も全ペアを確認し、A–B、B–CだけからA–Cを推定しません。
- 詳しいノード表示と全体ツリーは引き続き利用できます。

## 互換性と費用

古い結果からは上位概念を勝手に作りません。固定分類表による旧リンクも判定経路から外しています。古い結果を開くと再分析の案内を出し、ボタンを押した場合だけ新しいAI処理を実行します。

追加の上位概念は元の抽出要求に同梱するため、因数ごとの抽出LLM呼び出しを増やしません。ただし応答トークン、Embeddingの入力、必要なラベル生成は増えます。ラベル生成数には具体値と上位概念を合わせた上限を設けています。

保存済みの完全なCLI出力に上位概念ベクトルがあれば、`npm run replay`でAPIを使わず再評価できます。古い出力にそれらがなければ上位概念は再生成しません。

## 検証

学生の対象例に依存しないよう、仕入れ予測と生産計画を「需要予測」という上位概念で比較する模擬テストを追加しました。同じ因数のみの比較、独立したしきい値、nullの除外、元語の保持、削除リンク、保存済みデータでの再評価も確認しています。

実接続では4案の解析に成功し、対象以外にも課題・原因・目的・解決原理・利用場面の上位概念を取得しました。これは動作確認であり、あらゆる分野での意味精度を実証したものではありません。抽象度の揺れや過剰な一般化は今後評価する必要があります。
