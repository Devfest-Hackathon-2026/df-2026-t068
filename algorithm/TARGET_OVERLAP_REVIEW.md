# アイデア4のリンク漏れの調査

マッピング接続テストの保存済み結果を読み、追加のAI呼び出しなしで調査・修正した。

## 確認した内容

案1・2のターゲットは「大学初学者」、案4は「旅行好きの大学生」。元の抽出には大学生という対象が残っている。一方で語句全体を同じ因数で比較し、全因数に仮のしきい値0.82を適用していたため、共通する上位の対象を扱う経路がなかった。

保存済みWeb結果は、基準未満の比較スコアとEmbeddingを保存していない。したがって今回、1対4・2対4の過去の正確なコサイン類似度は復元していない。原因を特定のスコア値だったと断定していない。

## 問題点と採用した修正

1. **語句全体の類似と、対象の部分的共通性が区別されていない。**
   似ている語句をつなぐ既存の緑線に加え、「共通対象」の橙線を追加。1・4、2・4の大学生という共通性を明示する。元のターゲット値は変更しない。
2. **一律の基準を下げると別の意味まで同一視しかねない。**
   0.82は変更せず、共通対象を別判定にする。旅行中／授業後、学習の両立／講義理解などは同じとは断定しない。
3. **抽出表現が独自の短縮造語になりやすい。**
   プロンプトで「学習観光結合」のような機械的な連結を避け、一般的な語句を優先するよう修正。短くすれば必ず良いのではなく、意味を比較しやすい自然な表現を優先する。
4. **課題を言い換えただけのものが原因として出ている。**
   原因が入力から分からない場合はnullとし、課題の言い換えで埋めない指示を追加。旅行中に勉強できないという記述だけで、時間不足などを事実として作らない。
5. **リンクがない理由を画面で確認できない。**
   次回以降は全比較スコアと基準を軽量な表示用結果へ保存する。比較元・比較先を選ぶ表を追加。過去の未保存スコアは未記録と表示し、推測で数値を作らない。

## 共通対象判定の範囲

`src/overlap.ts`の保守的な分類規則を使う。既定の分類は大学生・高校生・中学生・小学生で、それぞれの表現を別名として扱う。対象語句の末尾を照合するため、「旅行好きの大学生」は大学生に含め、「大学生の親」は含めない。否定・除外表現も対象にしない。大学院生を大学生と同じにはしない。

これは任意の概念の包含関係を自動発見する汎用エンジンではない。関係の意味は「対象の一部が共通」であり、両案の対象全体や目的が一致するという意味ではない。新しい分野はConfig.targetConceptsで分類を追加できる。空配列にすると判定を無効化できる。

```json
{
  "targetConcepts": [
    { "id": "university-student", "label": "大学生", "aliases": ["大学生", "大学初学者", "大学新入生"] }
  ]
}
```

保存済みの画面結果にも、この分類だけを読み込み時に適用する。再分析、Embedding生成、保存データの書き換えは不要。プロンプトの改善が抽出内容に反映されるのは次回の分析から。

## 今回採用しない案

- すべての因数のしきい値を下げること：誤リンクの増加をまだ評価できない。
- 「学習」という単語があれば同じ課題や目的とすること：広い話題の一致と本質的な一致は異なる。
- LLMで全ペアを毎回再判定すること：コスト・遅延・判定の揺れが増える。評価用データを蓄積した後に候補を絞って検証する。

今後は複数分野の正例・負例で因数ごとのしきい値を評価する。今回の1例のために値を調整して精度向上を断定しない。
